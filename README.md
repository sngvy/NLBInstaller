# NLBInstaller (Not LTE Blocker)

**NLBInstaller** отслеживает публичные IP-адреса входящих подключений и автоматически блокирует адреса, которые сервисы [proxycheck.io](https://proxycheck.io/) и [ip-api.com](https://ip-api.com/) определяют как немобильные. Для блокировок используется `ipset`; поддерживаются IPv4 и IPv6.

Классификация по IP не гарантирует точного определения типа подключения: мобильный адрес тоже может быть ошибочно заблокирован. Чтобы исключить критичные адреса и сети из проверки и блокировки, используйте whitelist.

## Установка

```bash
bash <(curl -Ls https://raw.githubusercontent.com/sngvy/NLBInstaller/refs/heads/main/NLBInstaller.sh)
```

Запускайте от `root` на Debian/Ubuntu. Установщик запрашивает API-ключи и необязательный прокси, затем предлагает два независимых выбора:

**Источник IP-адресов:**

1. **Xray access.log** — анализ новых записей журнала Xray.
2. **conntrack** — отслеживание входящих соединений на уровне сетевого стека, независимо от Xray и порта назначения.

**Интеграция с файрволом:**

1. **UFW** — правила NLB в `before.rules` / `before6.rules`.
2. **iptables** — правила NLB в `raw` или `filter` в зависимости от источника IP.

Установщик устанавливает `ipset`, `curl`, `jq`, `logrotate` и необходимые компоненты файрвола. Для режима `conntrack` дополнительно требуются `conntrack` и `iproute2`; установщик ставит их автоматически.

При повторном запуске можно сохранить действующие ключи, прокси и оба выбранных режима, нажав Enter. Предусмотрен перенос старых блокировок в `ipset`.

> **Для сервера с SNAT/DNAT рекомендуются `conntrack` + `iptables`.** В этом сочетании NLB блокирует входящие подключения в `filter/INPUT` и перенаправленные DNAT-подключения в `filter/FORWARD`, а не все пакеты в `raw/PREROUTING`. Установщик не разрешает выбрать `conntrack` + UFW, если обнаруживает действующие правила NAT, поскольку переключение файрвола может нарушить их сохранение. Перед установкой на рабочем NAT-шлюзе проверьте собственные правила и сделайте резервную копию.

## Источники адресов

### Xray access.log

- Читает новые строки `access.log` (по умолчанию `/usr/local/x-ui/access.log`) и извлекает IP-адреса клиентов.
- Запоминает позицию и inode файла, учитывает ротацию и усечение лога. При первом запуске читает только последние 128 КиБ.
- Видит только подключения, попавшие в журнал Xray. Другие порты, службы и попытки без записи в лог не охватываются.

### conntrack

- Добавляет исходные IP новых входящих соединений в наборы `nlb_seen_v4` и `nlb_seen_v6` через правила `mangle/PREROUTING` с `--ctstate NEW --ctdir ORIGINAL`. Это сбор адресов, а не правило блокировки.
- Дополнительно просматривает текущую таблицу соединений командой `conntrack -L`, чтобы находить подключения к локальным адресам сервера.
- Не зависит от `access.log` и может учитывать короткие попытки подключения, не дошедшие до Xray. Отслеживаются IPv4 и IPv6, независимо от TCP/UDP-порта.
- Собранные адреса хранятся в `nlb_seen_*` с таймаутом 15 минут. Необработанные IP сохраняются в очередь `/var/lib/nlb/pending.list`.
- Адреса ответных пакетов уже отслеживаемых исходящих соединений не должны добавляться в сборщик благодаря проверке направления `ORIGINAL`. Пакеты, отброшенные до `mangle/PREROUTING`, и пакеты, не распознанные как `NEW`, сборщик может не увидеть.

В обоих режимах частные и служебные адреса отсеиваются перед классификацией.

## Где применяется блокировка

| Источник IP | Файрвол | Правило блокировки |
| --- | --- | --- |
| Xray access.log | iptables | `raw/PREROUTING`, по исходному IP из `nlb_ban_*` |
| Xray access.log | UFW | `ufw-before-input` / `ufw6-before-input` |
| conntrack | iptables | `filter/INPUT`; для перенаправленных подключений `filter/FORWARD` с `--ctdir ORIGINAL --ctstate DNAT` |
| conntrack | UFW | `ufw-before-input` и `ufw-before-forward` (IPv4/IPv6), с ограничением по DNAT для `FORWARD` |

В режиме `conntrack` + `iptables` ответы на исходящие соединения через SNAT не должны попадать под правило `FORWARD`, поскольку оно ограничено направлением `ORIGINAL` и состоянием `DNAT`. **Это не гарантия совместимости с любой конфигурацией NAT:** сторонние правила, порядок цепочек и сетевые схемы необходимо проверять на конкретном сервере.

## Как принимается решение

Новые IP проверяются параллельно через proxycheck.io и ip-api.com:

- Если **хотя бы один** сервис определил адрес как мобильный (`Wireless` или `mobile=true`), NLB не блокирует его.
- Иначе, если **хотя бы один** сервис определил адрес как немобильный (`Residential`, `Business` или `mobile=false` при успешном ответе ip-api.com), IP блокируется.
- Если оба сервиса не дали определённого результата, адрес не блокируется.

**Важно:** отрицательного ответа одного сервиса достаточно для блокировки, если второй не подтвердил мобильность. Поэтому ложные блокировки настоящих мобильных клиентов возможны. Это не строгий консенсус двух сервисов.

По умолчанию за запуск проверяется не более **20** новых адресов, остальные переходят в очередь. Повторные запросы сокращаются за счёт кэша: блокировка действует **7 суток**, мобильный IP кэшируется на **12 часов**, а неопределённый результат — на **10 минут**.

## Whitelist

Белый список хранится в `/usr/local/etc/nlb_whitelist.txt` и обновляется из репозитория приблизительно раз в час. Локально добавленные адреса и подсети сохраняются при пересборке списка. Записи whitelist не проверяются через API и исключаются из блокировки; существующие блокировки адресов из whitelist снимаются при применении списка.

Для немедленного применения изменений:

```bash
/usr/local/bin/update-nlb.sh whitelist
```

## Настройки

Файл `/etc/nlb/nlb.conf` (права `600`) содержит API-ключи, прокси и параметры:

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `SOURCE_MODE` | `xray` | Источник IP: `xray` или `conntrack` |
| `MODE` | `iptables` | Интеграция: `iptables` или `ufw` |
| `BAN_TTL` | `604800` | Время блокировки, 7 суток |
| `OK_TTL` | `43200` | Кэш мобильных IP, 12 часов |
| `ERR_TTL` | `600` | Кэш неопределённых результатов, 10 минут |
| `MAX_CLASSIFY` | `20` | Максимум проверок IP за запуск |
| `WL_INTERVAL` | `3600` | Интервал обновления whitelist, 1 час |
| `LOG_FILE` | `/usr/local/x-ui/access.log` | Путь к журналу в режиме `xray` |

Изменение `SOURCE_MODE` или `MODE` вручную в конфиге само по себе не перестраивает все правила файрвола. Для смены режима используйте установщик.

## Автоматизация и файлы

- `/usr/local/bin/update-nlb.sh` — обновлятор и команды управления.
- `/var/lib/nlb/ipsets.save` — сохранённые наборы `ipset`.
- `/var/lib/nlb/pending.list` — очередь адресов, ожидающих проверки.
- `/var/log/nlb_decisions.log` — результаты классификации и решения.
- `/var/log/nlb_update.log` — журнал запусков и ошибок.
- `nlb-ipset.service` — восстановление наборов до загрузки файрвола и установка правил сбора адресов.
- `cron` — запуск обновлятора каждые 2 минуты.

Основные наборы: `nlb_ban_v4/v6` (блокировки), `nlb_ok_v4/v6` (кэш разрешённых адресов), `nlb_wl_v4/v6` (whitelist). В режиме `conntrack` также создаются `nlb_seen_v4/v6` для собранных входящих IP.

## Полезные команды

```bash
# Применить обновление и обработать новые IP
/usr/local/bin/update-nlb.sh update

# Принудительно обновить whitelist
/usr/local/bin/update-nlb.sh whitelist

# Проверить/восстановить правила блокировки в режиме iptables
/usr/local/bin/update-nlb.sh ensure-rules

# Проверить/восстановить сбор IP в режиме conntrack
/usr/local/bin/update-nlb.sh ensure-source-rules

# Сколько адресов в бане и какие именно
ipset list -t nlb_ban_v4
ipset list nlb_ban_v4

# Собранные входящие адреса в режиме conntrack
ipset list -t nlb_seen_v4
ipset list -t nlb_seen_v6

# Снять блокировку с конкретного IPv4
ipset del nlb_ban_v4 203.0.113.10

# Посмотреть действующие правила NLB
iptables -t filter -S INPUT | grep nlb_ban
iptables -t filter -S FORWARD | grep nlb_ban
iptables -t mangle -S PREROUTING | grep nlb_seen
```

Последние три команды показывают правила для режима `conntrack` + `iptables`. В режиме `xray` + `iptables` блокировку следует искать в `iptables -t raw -S PREROUTING`.

Если появляется ошибка `Bad ctstatus "DNAT"`, используется устаревшая версия установщика или `/usr/local/bin/update-nlb.sh`: правильный параметр правила — **`--ctstate DNAT`**. Обновите установщик/обновлятор и проверьте установленные правила; отсутствие ошибки в журнале ещё не гарантирует, что блокировка в `FORWARD` действительно включена.
